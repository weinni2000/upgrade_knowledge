# web_ir_actions_act_multi: 19.0 -> 20.0

| Title | Explanation | Odoo Commit Hash |
| --- | --- | --- |
| `ir.model.access` merged into `ir.access` | Odoo 20.0 removes the `ir.model.access` model entirely, merging it with `ir.rule` into a single new `ir.access` model. Any module still shipping `security/ir.model.access.csv` (old columns `id,name,model_id:id,group_id:id,perm_read,perm_write,perm_create,perm_unlink`) fails to install with `KeyError: 'ir.model.access'` when its data file loads. Fix: rename the file to `security/ir.access.csv` and use the new column layout `id,name,model_id,group_id/id,operation,domain`, where `model_id` is the plain technical model name (resolved via `ir.model._rec_names_search = ('name', 'model')`, not an xmlid) and the four `perm_*` booleans collapse into one `operation` string such as `crud`, `r`, `cru`, etc. (see `CRUD_SELECTION` in `odoo/addons/base/models/ir_access.py`). This affects every module using the standard `ir.model.access.csv` convention, not just this one. | [77c17e7111c18fffe06fea9b9149cc6d3119e893](https://github.com/odoo/odoo/commit/77c17e7111c18fffe06fea9b9149cc6d3119e893) — `[ADD] core: new model ir.access that merges ir.model.access and ir.rule` (Part-of odoo/odoo#166359) |
| `PLW0642` (self-reassignment) now expected/suppressed by core | Ruff's `PLW0642` rule flags `self = self.with_context(...)` patterns. Odoo core itself uses this exact pattern in `odoo/addons/base/models/ir_model.py::IrModelData._module_data_uninstall` (`self = self.with_context(force_delete=True, prefetch_fields=False)`) and suppresses it with a `# noqa: PLW0642` comment rather than renaming the variable. Modules with a similar `self = self.with_context(...)` inside a `_module_data_uninstall`-style override (a common OCA pattern to guard shared-table uninstall, e.g. `ir_actions.act_multi`-style models reusing a core table) should do the same instead of refactoring the variable name. | same as above (core convention, not a single commit) |

## Notes

- No functional/API change was needed for `ir.actions.actions` inheritance patterns (`_get_readable_fields`, `_inherit = "ir.actions.actions"` with a custom `_table`), `_drop_table`/`_drop_column` overrides guarding a shared table, or the JS `action_handlers` registry (`registry.category("action_handlers")`, `env.services.action.doAction`) — all kept the same signatures between 19.0 and 20.0.
- Verified end-to-end: fresh install, `ir.access` row created correctly, clean `odev run --stop-after-init` boot, and `button_immediate_uninstall` leaves the shared `ir_actions` table and its data intact while fully removing the module's own `ir.model.data` records.
